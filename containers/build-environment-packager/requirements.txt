# Python environment of the build-environment packager image
# (containers/build-environment-packager/Dockerfile).
#
# This is NOT the build environment's dependency set — that one lives in
# `packaging/build-environment/requirements.txt` and is packed into the
# tools package as a wheel set. This file is the much smaller set the
# *packager* needs to produce those packages, and nothing else: no
# compiler tooling, no Zephyr build dependencies, no test tooling.
#
# Direct dependencies and why they are here:
#
#   west          lays the environment's west workspace out
#                 (`scripts/build_env_package.py`, materialize_workspace).
#                 One west lays a workspace out and the same west reads it
#                 later, so this pin MUST equal the build environment's —
#                 `tests/python/test_env_package.py` asserts every line
#                 below against `packaging/build-environment/requirements.txt`.
#   click,        CHIP's Matter code generators, which the workspace
#   coloredlogs,    package's pre-generation step runs
#   Jinja2,         (`scripts/codegen.py` and `scripts/tools/zap/generate.py`
#   lark            inside the pinned CHIP revision). The same four the
#                   build environment carries for the same generators.
#
# Fully pinned including the transitive closure, and installed with
# `--no-deps` followed by `pip check`: a dependency this file forgot then
# fails the image build instead of arriving unpinned. Transitive entries,
# and whose they are:
#
#   colorama, PyYAML, pykwalify, packaging     west
#   docopt, python-dateutil, ruamel.yaml       pykwalify
#   six                                        python-dateutil
#   MarkupSafe                                 Jinja2
#   humanfriendly                              coloredlogs
